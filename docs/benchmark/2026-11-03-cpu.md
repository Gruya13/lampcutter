# SAM 2 benchmark — CPU razvojna mašina

**Datum:** 2026-11-03. **Specifikacija:** 11.2 i 13.2. **Režim:** CPU (nema CUDA/MPS).

## Okruženje

| | |
|---|---|
| platforma | Linux x86_64 (Omarchy), 16 jezgara |
| RAM | 15 GB |
| GPU | nema (CUDA nedostupna, MPS nedostupan) |
| Python / torch | 3.12.16 / 2.14.1+cpu |
| SAM 2 | `facebookresearch/sam2 @ 2b90b9f5` (pinovan commit) |
| checkpointi | SAM 2.1 tiny/small/base_plus/large, SHA256 u `models/manifest.json` |
| ulaz | 3 **sintetička** mockupa (1200×1600 px): srce 200 mm, figura-8 220 mm, ploča sa rupom 150 mm |

> **Ograničenje:** sintetički uzorci imaju čist kontrast i simuliran sjaj ivice. Vremena
> su relevantna, ali kvalitet maske **nije** reprezentativan za stvarne fotografije
> upaljene lampe — to ostaje za Fazu E sa korisnikovim slikama (spec 13.3).

## Segmencija

| varijanta | učitavanje (s) | set_image (s) | predict (s) | RAM (MB) |
|---|---|---|---|---|
| tiny | 1.78 | 2.34 | 0.08 | 1142 |
| small | 0.47 | 2.54 | 0.07 | 1142 |
| base_plus | 0.74 | 4.27 | 0.08 | 1329 |
| large | 2.40 | 10.74 | 0.08 | 2163 |

`predict` je skoro nezavisan od varijante (dekoder je brz); cena je u enkoderu
(`set_image`). `large` traži 2,2 GB RAM samo za model.

## Odstupanje ivice u mm (spec 13.2)

| varijanta | srce (srednje / HD95) | figura-8 | ploča |
|---|---|---|---|
| tiny | **0.171 / 0.496** | **0.179 / 0.360** | 0.244 / 0.412 |
| small | 0.204 / 0.496 | 0.207 / 0.396 | 0.231 / 0.375 |
| base_plus | 0.281 / 0.496 | 0.217 / 0.396 | **3.348 / 19.492** |
| large | 0.143 / 0.496 | 0.213 / 0.396 | 0.998 / 12.188 |

PROVIZORNI pragovi za mockup: srednje ≤ 0,2 mm, HD95 ≤ 0,5 mm. Na ovim uzorcima
tiny i small su unutar praga (large je najbolji na srcu, ali neujednačen na ploči).

**Napomena o ploči:** base_plus/large su popunili rupu u obliku, pa je odstupanje
veliko. Za v1 je to **irelevantno** — spoljna kontura se ionako puni
(`fill_holes`, spec 7.4), ali pokazuje da varijanta menja interpretaciju unutrašnjih
otvora i da metrika mora da koristi referentnu masku bez rupa ili da meri samo
spoljnu ivicu.

## End-to-end (slika → SVG, bez `--debug-dir`)

Ulaz: `tests/data/srce.png`, tačka (600, 800), visina 200 mm, kerf 0,18 mm.

| varijanta | ukupno vreme | SVG platno (mm) |
|---|---|---|
| tiny | 5.44 s | 213.961 × 208.850 |
| small | **3.51 s** | 214.209 × 208.839 |
| base_plus | 5.32 s | 214.764 × 208.856 |

Spec 13.4 cilj „< 15 s na CPU sa `small`" je **ispunjen** (3,5 s, uključujući
učitavanje modela, segmentaciju, vektorizaciju, kerf i SVG).

## Zaključci

1. **CPU je upotrebljiv**: `small` je najbolji balans (set_image 2,5 s, predict 0,07 s,
   3,5 s end-to-end); `tiny` je najbrži na terenu, iste klase kvaliteta na ovim uzorcima.
2. **VRAM je glavni ograničavajući faktor na CUDA 4 GB**: `large` traži 2,2 GB RAM za
   model, a na CUDA verovatno više VRAM-a. Benchmark na RTX 3050 i Mac MPS ostaje
   obavezan (spec 11.2) pre konačnih podrazumevanih vrednosti.
3. **Odstupanje ivice na mockupima je na granici praga** (HD95 ≈ 0,4–0,5 mm), što
   potvrđuje da pragove 13.2 treba potvrditi na stvarnim fotografijama (Faza E).
4. Podrazumevana varijanta u kodu **nije menjana** na osnovu ovoga: odluka ide u
   Fazu 0b posle benchmarka na ciljnom hardveru.

## Kako pokrenuti na ciljnim mašinama

**macOS Apple Silicon (MPS):** PyPI `torch` wheel sadrži MPS, nema posebnog indexa:

```bash
uv pip install torch==2.14.1 torchvision==0.29.1
uv pip install setuptools wheel hydra-core iopath tqdm
uv pip install --no-build-isolation "sam-2 @ git+https://github.com/facebookresearch/sam2.git@2b90b9f5ceec907a1c18123530e92e794ad901a4"
uv run --no-sync python scripts/fetch_models.py --variants tiny,small,base_plus
uv run --no-sync python scripts/benchmark.py --images tests/data --variants tiny,small,base_plus,large \
    --reference-mm srce=200,figura8=220,ploca=150 --out benchmark_report
```

**Windows x64 sa RTX 3050 (CUDA 4 GB):** CUDA wheel (prati verziju drajvera; cu128 je
za Ampere generaciju):

```bash
uv pip install torch==2.14.1 torchvision==0.29.1 --index-url https://download.pytorch.org/whl/cu128
```

pa isto kao gore. Benchmark sam detektuje `cuda` → `mps` → `cpu`; na CUDA mašini
treba obratiti pažnju na `peak_vram_mb` (spec 11.1: `large` je isključen ispod ~8 GB).
